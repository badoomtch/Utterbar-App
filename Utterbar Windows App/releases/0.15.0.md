# Utterbar 0.15.0 (beta)

Real speaker diarisation in Meeting Mode. Beta channel.

## What's new

### Speaker labels in meeting transcripts

Meeting Mode transcripts now carry **`Speaker 1`**, **`Speaker 2`**, … labels per turn — derived from real voice-timbre clustering, not a guess based on which side was louder. The pipeline:

1. **Diarise** the full meeting audio with sherpa-onnx — pyannote 3.0 segmentation (MIT, CNRS) finds the speech-vs-silence boundaries, NVIDIA NeMo TitaNet small (CC-BY-4.0) embeds each segment as a 192-dimensional voice vector. A threshold-based clustering pass on those vectors yields per-segment speaker IDs.
2. **Transcribe** each speaker-bounded segment with Whisper Large.
3. **Stitch** the results into the canonical timestamped + labelled output:
   ```
   [00:00] **Speaker 1:** Welcome to the call.
   [00:14] **Speaker 2:** Sounds good.
   ```

Works for solo speakers, two-speaker calls, and small group meetings. No mic-vs-loopback split assumption — the diariser works from voice timbre on the mixed buffer alone.

### Rename speakers from the Meetings page

Open a meeting, click any **Speaker N** label to rename it. The rename map persists per-row; exports (`.txt`, `.md`) and clipboard copies use the renamed labels. The raw transcript stays canonical, so you can re-rename or clear renames freely.

### One-time download on first meeting

The diariser models (~47 MB compressed: pyannote segmentation + NeMo TitaNet small) download from the same upstream GitHub release host as the existing Whisper Large model. SHA-256 pinned, traversal-protected extraction, group-policy-gated (`BlockModelDownloads` already covers it).

## What's fixed

- Meeting Mode without Whisper Large no longer silently falls back to Parakeet. v0.14.x would happily run a meeting with the wrong model and you'd never know; v0.15.0 refuses with a clear *"Meeting mode needs Whisper Large. Install it from Settings → Models, then start the meeting again."*
- The v0.14.3 placeholder where speaker tags were "suppressed until a heuristic that works" is replaced by the proper diarised path. The dead RMS-classifier code is removed.

## What's the same

- Dictation mode (non-meeting) — unchanged. Same Parakeet TDT v3 default, same hotkey latency, same audio path post-v0.14.11.
- Pricing (£39.99 GBP one-time Pro), licence, updater, history, modes — all untouched.
- Old meeting transcripts (v0.13.x — v0.14.x) render exactly as they always did. The substitution is a no-op on transcripts that don't contain `**Speaker N:**` tokens.

## Attribution

The diariser pulls in two new third-party models, both with licences that require attribution:

- **NVIDIA NeMo TitaNet small** — speaker embedding (CC-BY-4.0)
- **pyannote/segmentation 3.0** — speaker segmentation (MIT, © 2022 CNRS)

Full attribution is at **Settings → About → Third-party licences** and at `THIRD_PARTY_LICENCES.md` in the repo.

## What this does NOT change

- The fallback path. If diarisation can't run (assets missing, model load error, edge-case panic), Meeting Mode still produces a transcript — bounded chunked transcription with `[mm:ss] text` timestamps and no speaker labels. Same `CHUNK_SECONDS = 30` / `OVERLAP_SECONDS = 2` shape as v0.13.x — v0.14.x meeting output (the implementation plan loosely mentioned 5s overlap as a placeholder; the production value has been 2s since meeting mode shipped, and v0.15 keeps it). Toast informs you that labels weren't available for this recording.
- File transcription, the floating bar, the security-hardened publish flow from v0.14.13 — none of that is touched.

## Beta soak

Tuning the clustering threshold (`0.5` default) needs real-recording data. If a meeting comes back with the wrong number of clusters, the log line `diarisation complete segment_count=N distinct_speakers=M speakers=...` in `%APPDATA%\Utterbar\logs\` is the diagnostic — that lands on every meeting and feeds the threshold tuning.
