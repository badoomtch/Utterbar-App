# Utterbar 0.14.0 (beta)

The Meetings page. Beta channel — soaking before promotion to stable.

## What's new

**Meetings have their own home now.** Sidebar has a new "Meetings" entry alongside History, Modes, Vocabulary, Files. Anything you record with a Meeting Mode mode (the built-in Meeting, or any custom mode you've flipped the meeting flag on) lands here instead of cluttering up /history.

### List view

Card per meeting:
- Date + time
- Duration (mm:ss)
- Speaker breakdown — counts of `**You**` and `**Other**` turns derived from the per-chunk speaker tags
- A one-line preview from the body (timestamp + tag stripped so you actually see content)
- Mode name on the right

### Detail view

Click into a meeting:
- Full timestamped, speaker-tagged transcript in a monospace block, paragraph-per-chunk
- **Copy** button — full transcript to clipboard
- **.txt export** — plain transcript, no formatting
- **.md export** — transcript with a small YAML front-matter block (date, duration, mode) so a re-import or LLM consuming the file has the metadata it needs
- **Delete** button — removes the row (audio file too if `retain_audio` was on)

### Summary slot

There's a "Summary" section on the detail view, currently a placeholder. The offline LLM (small instruction-tuned model running locally via llama.cpp) lands in v0.14.1 — at that point the placeholder becomes a clickable Generate Summary button. Shipping the slot now means v0.14.1's only visible change is "the button works".

## Changes to /history

The History page now excludes meeting rows. Before this release, a meeting was just a long awkward row in the dictation table — preview cut off, "1m32s" duration unparsable next to "0:01" dictations. Now meetings live on /meetings; /history stays clean for short dictations.

If you have a meeting in history from v0.13.x and want to keep it visible there, there's no migration path — meeting rows had no flag prior to v0.14.0. The new column defaults to 0 for existing rows, so any meetings you recorded before this release will still appear in /history (since they're tagged as not-meetings) but they will not appear in /meetings. Going forward, every Meeting Mode recording is tagged at insert time and ends up on the right page.

## What's not in this release

- **LLM summary generation** — placeholder only; v0.14.1
- **Audio playback in detail view** — needs a player component + the audio_path to be readable from the webview; v0.14.x or v0.15
- **.docx export** — `.txt` and `.md` cover most workflows; .docx adds significant dependency surface for limited gain
- **The full background queue** ("record a second meeting while the first transcribes") — still blocked on safely lifting the heap-corruption-defence guard. Workaround for now: wait for the meeting to finish transcribing (the bar shows "Transcribing meeting…" so you know what's happening) before starting the next.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log. `crash.log` has any panic traces. Send the newest files to `hello@ddraig.dev`.
