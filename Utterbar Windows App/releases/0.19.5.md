# Utterbar 0.19.5 (beta)

A small beta performance pass on top of v0.19.4. Stable channel still serves v0.19.0.

## Read this first

This is a beta performance release. Stable users remain on v0.19.0. v0.19.5 continues the beta soak that v0.19.1, v0.19.2, v0.19.3, and v0.19.4 started, with no new features and no behaviour changes you would notice except for two specific things being faster:

- The first dictation after you launch Utterbar is no longer cold for default users.
- The Utterbar floating bar window opens faster after launch.

Everything else is the same as v0.19.4.

## What this release improves

- **First dictation after launch is no longer cold.** Previously, the very first time you pressed your dictation hotkey after launching Utterbar, Utterbar had to load your speech recognition model into memory before it could transcribe. Depending on your model and GPU, that first transcription took roughly half a second to four seconds longer than every subsequent one. From v0.19.5, Utterbar starts loading your default model in the background at launch, so by the time you press the hotkey the model is usually already warm. You only pay the cold load cost on the very first launch on a new install (because Utterbar has to download the model first); after that, every launch starts with a warm model. If you have set "Keep model loaded" to "Never" in Settings, Models, that opt-out is honoured and Utterbar does not pre-load anything.
- **The floating bar window opens faster after launch.** The floating bar (the dictation pill that appears at the top of your screen) used to load every screen Utterbar has, including all of Settings, the History view, the Files view, the Meetings view, and the onboarding flow, just to draw the pill. From v0.19.5, the bar only loads what it needs to draw itself. The other screens load on demand the first time you open them, and stay loaded for the rest of the session. Net effect: the pill is ready sooner after launch, and opening Settings or History for the first time after launch may take an imperceptible extra moment to fetch the screen.
- **Less work happens per dictation.** Several small per-transcribe operations that turned out to do nothing useful have been removed. No user-visible behaviour change; the work was invisible to begin with.

## What this release does not change

- **The app interface is still English only.** No second language pack ships in this release.
- **Speech recognition behaviour is unchanged.** No change to Whisper, Parakeet, or Zipformer. Transcripts are byte-identical to v0.19.4 for the same audio, model, and language settings.
- **No speech model change.** No new model files, no model removals, no checksum changes for any installed model.
- **No audio capture change. No microphone routing change. No mic-mute change.**
- **No GPU acceleration change.** DirectML, CUDA, and CPU-only paths all behave as in v0.19.4.
- **No change to the auto-update flow.** The Install & restart first-click fix from v0.19.4 is unchanged.
- **The Settings, Models language-compatibility warning is unchanged.** Same placement (beside the Whisper language picker), same one-click switch behaviour, same install hint when no multilingual model is installed.
- **Settings, Vocabulary is unchanged.** Your custom words and replacements work exactly as before.
- **Settings layout, hotkeys, and the floating bar's appearance are unchanged.**
- **No licence change. No Stripe change. No website change. No analytics, no telemetry, no local LLM rewrite.**
- **No new outbound network calls from the desktop app.**
- **Stable users remain on v0.19.0** unless they opt into the beta channel from Settings, Updates.

## If you hit a problem

The app log is at `%APPDATA%\Utterbar\logs\`. If you notice your first dictation after launch is still cold (taking noticeably longer than subsequent ones), please email hello@ddraig.dev with:

- the log file from `%APPDATA%\Utterbar\logs\`,
- the model you have selected as your default in Settings, Models,
- the GPU acceleration setting in Settings, Advanced,
- whether the cold delay happens every launch or only sometimes.

If you notice the bar window taking longer to appear than on v0.19.4, that is also worth reporting with the same log files.
