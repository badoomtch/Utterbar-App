# Utterbar 0.8.5

Auto-update relaunch — proper fix this time. The PowerShell watcher is gone; the relaunch now happens inside the NSIS installer itself.

## Auto-update

- **Relaunch is driven by NSIS, not by a separate watcher script.** When the installer was invoked silently (i.e. by the in-app updater), the install script's post-install hook now runs `ExecShell` to launch the freshly-installed Utterbar via Windows' shell. This is how Squirrel.Windows / VS Code / Slack / Discord do it: the relaunch is a child of the installer, fully detached, no shell scripting, no path-quoting bugs, no timing assumptions about when NSIS is done.
- **Earlier PowerShell-based watchers are removed.** v0.7.5 through v0.8.3 tried five different variants of "spawn a script that waits then re-launches" — none of them survived antivirus / SmartScreen / managed Windows installs reliably. The script approach is fundamentally fragile because it runs outside the install process. Letting NSIS do its own relaunch sidesteps the whole class of bug.
- **Manual installer runs (user double-clicks the .exe) still skip the auto-launch.** Only the silent path triggered by the in-app updater relaunches. Means a fresh first install doesn't surprise-open the app before the user expects it.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log and any crash dumps. Send the newest files to support and we'll take a look.
