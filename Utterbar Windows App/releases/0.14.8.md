# Utterbar 0.14.8 (beta)

Hotfix on top of v0.14.7. Beta channel.

## Recording works again

v0.14.7 broke recording on some Windows mics. The capture-rate picker introduced in 0.14.7 was choosing the highest-rate config the device supported, but it didn't filter on sample format. On some mics (Intel Smart Sound integrated mic, certain Focusrite configurations) the highest-rate config delivers samples in U8 format, which our cpal callback dispatch doesn't decode. Result: every recording produced "unsupported sample format: U8" and exited the capture thread.

Fix: the picker now filters candidate configs to formats we can decode (F32, I16, U16) before choosing rate. Picks the highest rate up to 48 kHz from that filtered set. Falls through to the v0.14.6 default-config behaviour if the device exposes no F32/I16/U16 ranges, which on real installs would point at a driver problem rather than us.

So the v0.14.7 audio-quality fix still applies (capture at 48 kHz when the device supports it) but recordings work again on every mic the previous versions worked on.

The "audio capture stream opened" log line still tells you what rate and format you got. After this update the format will be one of F32/I16/U16, and src_rate will be 48000 wherever the device supports it.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log. Send the newest files to `hello@ddraig.dev`.
