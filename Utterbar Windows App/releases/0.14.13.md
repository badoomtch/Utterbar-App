# Utterbar 0.14.13 (beta)

Security/stability patch. Beta channel.

No user-visible behaviour changes on the dictation path — every fix
here is structural. v0.14.12's mic-routing logic is unchanged.

## What changed

### Diagnostics opener

The "show in folder" buttons in Settings → Advanced previously
shelled through `cmd /C start <path>` with the path passed verbatim.
Characters like `&`, `|`, `>` would have been shell metacharacters in
that path, turning a future maliciously-crafted path into a command
injection. Replaced with a direct `ShellExecuteW` call (no `cmd.exe`),
plus a containment check that restricts the opener to the Utterbar
data directory (logs, db, models, recordings, diagnostics audio dump).
Anything outside is refused with a clear error.

### Model deletion path safety

The model uninstall and the v0.8 / v0.14.2 retirement-prune flows
all called `models_dir.join(rel).remove_dir_all()` where `rel` came
from a sqlite `TEXT` column. `Path::join` has surprising behaviour
for absolute paths and `..` components — a corrupted DB row could
have nuked something outside the models directory. Now: absolute
paths and `..` traversals are rejected up front, and the joined
target is canonicalised + checked to live under `models_root`
before any deletion.

### Release publishing

Three behind-the-scenes changes operators of the publish script
won't notice but the next stable release depends on:

- The website now **recomputes SHA-256 from R2** after upload and
  refuses publish if the pasted SHA doesn't match. The persisted
  hash is the value the server computed, not the pasted one — so a
  wrong-file-uploaded scenario surfaces as a clear validation error
  rather than a release row that the desktop updater would refuse
  forever.
- Updater signatures are now verified against the **computed** SHA,
  not the pasted one — closes a loophole where a wrong pasted SHA
  could drag a valid-looking signature with it.
- The browser admin form now requires `updater_signature` on the
  same conditions as the headless API. Stable + announce requires
  an explicit confirmation tickbox.

`publish-release.sh` automatically sets the new
`confirm_stable_announce` flag when `--announce` is on a stable
channel, so existing CLI invocations keep working.

### Website Markdown rendering

Release notes and blog posts are rendered via `{!! ... !!}` (no
auto-escape) so the underlying CommonMark conversion has to be safe
on its own. The default config let raw `<script>`, `<iframe>`, and
`javascript:` URLs through. Now: raw HTML is stripped at parse time
and unsafe URL schemes (`javascript:`, `data:`, `vbscript:`) are
neutralised. Normal markdown formatting (headings, links, lists,
code blocks, emphasis) still works.

### Tauri capabilities scope

Dropped `fs:default` and `core:path:default` from the desktop app's
capability set. The frontend doesn't import either plugin, so they
were dead weight. Other capabilities left in place — narrowing
further would need real runtime QA across every flow.
