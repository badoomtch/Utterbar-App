# Utterbar 0.21.3 (beta)

A small clipboard-control beta on top of v0.21.2. Stable users remain on v0.21.0.

## What this release adds

You can now choose how long Utterbar waits before restoring the clipboard after a dictation.

Open **Settings, Text Output, Delivery** and use **Clipboard restore delay**. The slider offers values from 250 ms to 1,500 ms, in 250 ms steps. The existing 1,500 ms setting remains the default because it gives slower apps more time to receive the pasted transcript.

Lower values restore your copied text or image sooner. If a target app occasionally misses a paste, move the delay back up and try again. The control is disabled when **Restore previous clipboard** is off.

The delay changes only when your previous clipboard contents return. It does not delay transcription or the initial paste into your active app.

## What this release does not change

- **No change to speech recognition, models, audio capture, Meeting Mode, or graphics acceleration.**
- **No change to transcript insertion before the clipboard restoration step.**
- **No change to copied-image restoration introduced in v0.21.2.**
- **No change to the App language picker or interface translations.**
- **No change to the licence system, Stripe, price, or activation flow.**
- **No new outbound network calls, analytics, telemetry, or local LLM rewrite.**
- **Stable users remain on v0.21.0** unless they select the beta channel in Settings, Updates.

## Test this beta

Copy text or an image, dictate into a text field, then paste somewhere else after Utterbar finishes. Try a lower delay first. If the target app misses the transcript, increase the delay and report the app name and the value that worked.

The app log is at `%APPDATA%\Utterbar\logs\`. If anything goes wrong, email hello@ddraig.dev with the log file, the target app, and the clipboard restore delay you selected.
