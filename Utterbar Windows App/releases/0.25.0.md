# Utterbar 0.25.0

## Media playback pauses reliably while you dictate

When **Pause media while recording** is enabled in Settings, Privacy, Utterbar now waits for active music or video playback to pause before it starts listening. It resumes only the playback sessions that it successfully paused when your dictation finishes.

This fixes cases where a fast hotkey press could start dictation while music or video continued playing.

## Better diagnostics if a media app does not respond

Utterbar now records whether Windows found a media session and whether that app accepted the pause or resume request. This does not add telemetry or send anything away from your device. It makes a remaining compatibility problem easier to diagnose from your local app log.

## What this release does not change

- Media pausing still applies only to microphone dictation, not System audio or Mixed capture.
- The setting remains optional and stays where it is: Settings, Privacy, Pause media while recording.
- Speech recognition, installed models, audio capture, clipboard handling, GPU acceleration, licensing, updates, and the experimental Teams and Discord microphone mute are unchanged.
- Utterbar remains local-first. No new outbound calls, analytics, or telemetry are included.

## If playback still does not pause

Check that **Pause media while recording** is enabled in Settings, Privacy. Then send `%APPDATA%\Utterbar\logs\` to hello@ddraig.dev with the name of the app that was playing media and whether it was playing music, video, or a browser tab.
