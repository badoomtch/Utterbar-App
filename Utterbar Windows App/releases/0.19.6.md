# Utterbar 0.19.6 (beta)

A small beta hotfix on top of v0.19.5. Stable channel still serves v0.19.0.

## Read this first

This is a beta hotfix. Stable users remain on v0.19.0. v0.19.6 continues the same beta soak that v0.19.1, v0.19.2, v0.19.3, v0.19.4, and v0.19.5 started, with one fix that restores an experimental feature on the beta channel.

## What this release fixes

The experimental Teams and Discord microphone-mute toggles now actually fire while you are dictating, on the beta channel. In recent v0.19.x beta builds the toggle in Settings, Advanced, Experimental could appear enabled but the mute or unmute keystroke was never sent to the call app. v0.19.0 stable was unaffected; only the v0.19.x beta builds had this regression. v0.19.6 restores the same behaviour stable v0.19.0 had.

If you do not have the Teams or Discord mic-mute toggles turned on, this release changes nothing for you. The feature is opt-in, off by default, and most users will not notice anything.

If you have either toggle turned on:

- **Teams mic mute now fires while recording.** With the configured Teams mute hotkey set in Settings, Advanced, Experimental, starting a dictation now sends that hotkey to Teams. The people on your call no longer hear you while you dictate.
- **Discord mic mute now fires while recording.** Same as Teams, with the configured Discord mute hotkey, including when Discord is minimised to the tray.
- **Restore on stop fires after recording.** When the dictation ends, the same hotkey is sent again to unmute, so you are audible again on your call.
- **The unmissable banner still appears under the floating bar.** It asks you to glance at the call app's own mute indicator and confirm. We do not read the call app's state and we do not promise the mute landed; the banner is the honest backstop in case the keystroke missed.

## What this release does not change

- **The feature remains experimental and off by default.** No automatic enablement; you have to turn it on yourself in Settings, Advanced, Experimental.
- **Teams and Discord only.** Zoom and Webex are not supported by this feature, by design. Use those apps' own mute buttons or hardware mute.
- **The app still asks you to check the call app's mute indicator.** The banner under the floating bar is the same honest backstop as before. We do not read the call app's microphone state.
- **Auto-paste behaviour after a mic-mute dictation is unchanged.** The transcribed text still lands in the original target window, not in the call app, just as on v0.19.0 stable.
- **The app interface is still English only.** No second language pack ships in this release.
- **Speech recognition behaviour is unchanged.** No change to Whisper, Parakeet, or Zipformer.
- **No speech model change.** No new model files, no model removals, no checksum changes for any installed model.
- **No audio capture change. No microphone routing change.**
- **No GPU acceleration change.** DirectML, CUDA, and CPU-only paths all behave as in v0.19.5.
- **No change to the auto-update flow.** The Install & restart first-click fix from v0.19.4 is unchanged.
- **No change to the Settings, Models language compatibility warning.** Same placement, same one-click switch behaviour.
- **No licence change. No Stripe change. No website change. No analytics, no telemetry, no local LLM rewrite.**
- **No new outbound network calls from the desktop app.**
- **Stable users remain on v0.19.0** unless they opt into the beta channel from Settings, Updates.

## If you hit a problem

The app log is at `%APPDATA%\Utterbar\logs\`. If the Teams or Discord mic-mute toggle is on but recording does not seem to mute the call app, please email hello@ddraig.dev with:

- the log file from `%APPDATA%\Utterbar\logs\`,
- which call app you are using (Teams, Discord, both),
- the configured mute hotkey for that app (Settings, Advanced, Experimental),
- whether the call app was visible, in the background, or minimised to the tray when you started recording.
