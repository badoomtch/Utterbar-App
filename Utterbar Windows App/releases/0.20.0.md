# Utterbar 0.20.0

A stable release on top of v0.19.0. Bundles the soaked v0.19.1 to v0.19.6 betas into a single stable cut.

## Read this first

If you are on stable v0.19.0, this is your next available update. The user-visible work in this release is concentrated on three things: setting up Utterbar for non-English dictation, making the first dictation after launch noticeably faster, and tidying the auto-update flow so Install & restart applies on the first click. Everything else, including all of speech recognition, audio capture, GPU acceleration, the speech models, and the experimental Teams and Discord microphone mute, is unchanged from v0.19.0. The app interface itself is still English only.

If you have been running a beta from the v0.19.x line, you have already seen most of this. v0.20.0 is the consolidated stable cut.

## What is new

### Better setup for non-English dictation

Onboarding now has a step that asks what language you intend to dictate in. The default is Auto-detect, which is the same behaviour Utterbar has always had: the speech engine decides per utterance. If you pick a specific language other than English, Utterbar guides you towards a multilingual Whisper model on the next step, because the default English recommendation (Parakeet) is English only. If you keep Auto-detect or pick English, the recommendation is unchanged.

The dictation language you pick is stored separately from the app interface language, which remains English only in this release. The new step controls only what Utterbar listens for, not what the app reads as.

### Clearer model guidance in Settings

Settings, Models now warns you when your dictation language is non-English but your default model is English-only. The warning appears directly below the Whisper language picker, so the cause and the message are visually adjacent. In v0.19.0 there was no such warning, so it was possible to set Whisper language to French or Spanish in Settings while leaving the default model on Parakeet, and nothing told you the two choices were incompatible.

When you see the warning:

- If you already have a multilingual Whisper model installed, a "Switch to multilingual model" button appears. Clicking it sets your default model to the installed multilingual model. No download.
- If you do not have a multilingual Whisper model installed, an amber card asks you to install one from the model list further down. Nothing is installed automatically.

If you keep Whisper language on Auto-detect or English, no warning appears. The Default model picker, the Whisper language picker, and the Meeting mode picker behave exactly as on v0.19.0.

### Foundation for future language packs

A large amount of internal plumbing was reworked so most Settings panes, the onboarding flow, the floating bar chrome, the update prompts, and the main-window shell now resolve their visible text from a shared English catalogue rather than being scattered across the source. The wording you see is the same wording v0.19.0 had; the change is structural, not phrasing.

This is groundwork for future language packs. **No non-English UI language pack ships in this release.** The app interface is still English only, and is intentionally so until a non-English pack is genuinely ready. You should see no difference compared with v0.19.0.

### Faster first dictation after launch

When you launch Utterbar, it now starts loading your default speech model in the background, so your first hotkey press after launch is usually warm rather than cold. On v0.19.0, the first dictation after every launch paid the full cold-load cost (roughly half a second to four seconds depending on your model and GPU). On v0.20.0 you only pay that cost on the very first launch on a new install (because the model file is not on disk yet); after that, every launch starts with a warm model.

If you have set "Keep model loaded" to "Never" in Settings, Models, your opt-out is honoured: Utterbar does not pre-load anything, idle RAM stays free between dictations, and the first dictation after each launch pays the cold load as before.

### Faster floating bar startup

The floating bar window (the dictation pill) used to load every screen the app has, including all of Settings and the History view, just to draw the pill. v0.20.0 only loads what the bar needs to draw itself. The other screens load on demand the first time you open them, and stay loaded for the rest of the session.

Net effect: the pill is ready sooner after launch, and the first time you open Settings or History after launch may take an imperceptible extra moment as the screen fetches; every subsequent open is instantaneous.

### Less work happens per dictation

Several small per-transcribe operations that turned out to do nothing useful have been removed. No user-visible behaviour change; the work was invisible to begin with. Transcripts are byte-identical to v0.19.0 for the same audio, model, and language settings.

### More reliable updates

When the next update offers itself in-app, **Install & restart now applies on the first click** instead of sometimes hiding the app to the tray and needing a second click. The previous interaction was: the updater asked Utterbar to exit so the new version could overwrite it on disk; Close to tray (which is on by default) intercepted that exit as if you had clicked the X button. The new installer never got to run, the running app stayed open, and the update silently did not apply.

v0.20.0 teaches Close to tray to recognise the updater's exit and let it through. Normal clicks on the X button still go to the tray exactly as before. Tray quit, normal startup, and normal shutdown are all unchanged. A small bonus fix: a fast double-click on Install & restart only fires the install once.

A note on this upgrade itself: the fix is in the v0.20.0 binary, so it takes effect for updates that you receive **after** reaching v0.20.0. If you are on v0.19.0 today with Close to tray turned on, your upgrade to v0.20.0 may still hide to the tray on the first click of Install & restart; reopen Utterbar from the tray and click Install & restart again, and the v0.20.0 installer will run. From v0.20.0 onwards, one click is enough.

### Experimental Teams and Discord mic mute, kept working through the cut

The experimental Teams and Discord microphone mute (Settings, Advanced, Experimental) is the same opt-in feature v0.19.0 already shipped. It mutes you inside Teams or Discord while you are dictating, by sending the configured mute hotkey, and unmutes you when you stop.

You will not see a behaviour change between v0.19.0 stable and v0.20.0 stable on this front. We mention it here because keeping this feature working through the v0.19.x beta line, and the way release builds are produced, took deliberate effort. Nothing about the runtime or the user experience changed. The same caveats from v0.19.0 still apply:

- **Teams and Discord only.** Zoom and Webex are not supported.
- **Off by default.** You have to turn it on yourself.
- **No automated verification.** Utterbar sends a keystroke and trusts the app received it. The banner under the floating bar asks you to glance at the call app's own mute indicator and confirm. Always check the call app itself.

## What has not changed

- **The app interface is still English only.** No non-English UI language pack ships in this release. The dictation language step controls only what Utterbar listens for, not what the app reads as.
- **Speech recognition behaviour and model quality are unchanged.** No change to Whisper, Parakeet, or Zipformer. Transcripts on identical audio, model, and language settings are byte-identical to v0.19.0.
- **No new speech models.** No model files added or removed, no checksum changes for any installed model.
- **No audio capture change. No microphone routing change.** Same mic input path, same loopback path for system audio.
- **No GPU acceleration change.** DirectML, CUDA, and CPU-only paths all behave as on v0.19.0.
- **No licence change. No Stripe change. No purchase or activation flow change.** Same one-time £39.99 GBP, same three-device cap, same offline activation flow.
- **No website change as part of this release.**
- **No new outbound network calls from the desktop app.** Same five outbound calls as v0.19.0 (model catalogue lookup, model download, licence check, update check, conferencing-mute app list resolution).
- **No analytics, no telemetry, no local LLM rewrite.** Smart rewrite remains the deterministic rule-based pipeline shipped in v0.16.4.
- **The auto-updater backend is unchanged.** Same updater feed, same signed-update verification.
- **Mic-mute behaviour is unchanged from v0.19.0.** Same caveats, same default-off, same Teams and Discord only, same banner asking you to confirm.
- **Settings layout, hotkeys, and the floating bar's appearance are unchanged.** No new settings rows, no removed settings rows, no relocated controls beyond the language warning described above.

## If you hit a problem

The app log is at `%APPDATA%\Utterbar\logs\`. If something misbehaves after upgrading to v0.20.0, please email hello@ddraig.dev with:

- the log file from `%APPDATA%\Utterbar\logs\`,
- the version reported in Settings, About,
- the dictation language you have selected (Settings, Models, Whisper language),
- the default model you have selected (Settings, Models, Default model), and
- whether the issue happened during an update, during dictation, or while using the experimental Teams or Discord mic mute.

That last detail in particular helps us narrow the diagnosis quickly.

## Stable channel

This release supersedes v0.19.0 on the stable channel. Beta-channel users on the v0.19.x line (v0.19.1 through v0.19.6) will see v0.20.0 as the next available stable release. The v0.19.1 to v0.19.6 beta rows remain in admin as historical soak records. If you have been running a beta and want to stay on stable from now on, switch the channel in Settings, Updates after upgrading.
