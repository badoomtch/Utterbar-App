# Utterbar 0.15.2 (beta hotfix)

Fixes a launch crash introduced in v0.15.1. Beta channel only.

## What this fixes

v0.15.1 panicked at startup on every machine that had run v0.15.0 first, with the error:

> applied migration V6\_\_history_speaker_names is different than filesystem one V6\_\_history_speaker_names

The bytes of the V6 SQL migration file differed between the v0.15.0 and v0.15.1 builds (Windows `core.autocrlf` rewrote the working tree from LF to CRLF between the two `tauri build` runs). The v0.15.0 binary recorded the LF hash in your local DB; v0.15.1 shipped the CRLF version; refinery — the migrations runner — refused to start with mismatched hashes (intentional, as a safety guard).

## What v0.15.2 does

- **Restores the V6 migration to its v0.15.0 byte content.** The hash matches what's already in your DB; v0.15.2 launches normally for users whose DB recorded the LF hash (everyone who first launched 0.15.x on v0.15.0).
- **Repairs DBs that recorded the v0.15.1 CRLF hash.** Some users' first 0.15.x launch was v0.15.1 — for them the LF-only fix above would still fail in the opposite direction. v0.15.2 runs a narrow pre-migration check that detects the v0.15.1 CRLF checksum on the V6 row, confirms the migration's effect (the `history.speaker_names` column) is actually present, and rewrites only that row's checksum to the LF value. Anything else — unknown checksum, missing column — is left untouched and refinery's normal divergence path runs.
- **Adds a `.gitattributes` rule pinning `*.sql` and release-note Markdown to LF endings.** Refinery-bundled migrations are now safe from line-ending drift across platforms — this class of bug can't reoccur.
- **Adds unit-test pins on every migration's SHA-256 + the V6 SipHasher13 LF/CRLF values.** Any future drift fails CI before it can ship.

No app behaviour changes. Meeting Mode still uses the v0.15.1 chunked-no-labels path; speaker diarisation remains disabled pending the architectural rework now planned for v0.15.3.

## What's the same as v0.15.1

- Meeting Mode produces `[mm:ss] text` chunks with no `**Speaker N:**` labels.
- The ~60-minute meeting cap.
- The Whisper-language-pin workaround for cross-language hallucinations.
- Dictation mode, pricing, licence, updater, history, modes, file transcription, floating bar — all unchanged.

## If v0.15.1 won't launch on your machine right now

The auto-updater can't fix you because v0.15.1 doesn't reach the point where the updater runs. Either:

1. Wait for v0.15.2 to land on the beta channel and download the installer manually from `https://dl.utterbar.com/releases/0.15.2/Utterbar-Setup-0.15.2.exe`.
2. Reinstall v0.15.0 to get back to a working state immediately: `https://dl.utterbar.com/releases/0.15.0/Utterbar-Setup-0.15.0.exe`. v0.15.2 will then auto-update over it cleanly.

## Beta only

Beta-channel hotfix. Stable channel is intentionally unchanged. Speaker labels stay disabled until the v0.15.3 architectural rework ships and proves out on real meetings.
