# Utterbar 0.14.6 (beta)

Bar refresh on favourite toggle. Beta channel.

## Unfavouriting a mode now removes its chip from the bar

In v0.14.5 favouriting and unfavouriting a mode in Settings → Modes updated that page's local list, but the floating bar's quick-switcher kept rendering the old set of chips. The bar's mode store wasn't being told that anything had changed.

Fix: `upsert_mode`, `delete_mode`, and `duplicate_mode` now re-emit `settings:changed` after the DB write. The shared modes store listens for that event and reloads the full mode list. Favouriting a custom mode in Settings → Modes immediately adds its chip to the bar; unfavouriting removes it. Same channel for cross-window sync as `set_active_mode`, no new event types.

## Note on the Parakeet accuracy report

In the v0.14.5 testing you mentioned Parakeet's accuracy felt worse. Audited the diff between v0.14.3 and v0.14.5 to confirm: zero changes in `dictation.rs`, `audio/`, or `inference/`. The Parakeet code path is byte-identical to what shipped in v0.14.3.

If you still notice it on v0.14.6, the next step is grabbing the relevant lines from `%APPDATA%\Utterbar\logs\utterbar.log.<date>` — search for `parakeet transcribe done` and the per-line `samples=N rms=R chars=C` values. If `rms` is normal but `chars/samples` is low, the model is silent on real speech (real bug). If `rms` itself is low, the mic level has dropped (Windows audio focus / gain side-effect, fixable by checking your default device).

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log. Send the newest files to `hello@ddraig.dev`.
