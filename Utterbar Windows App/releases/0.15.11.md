# Utterbar 0.15.11 (beta)

First B2B-facing release of the v0.15.x line: Utterbar can now be deployed across a managed fleet without each user pasting a licence key, and IT admins get three new group policy keys to pin privacy posture across machines they manage.

This is a beta-only drop. Stable channel still serves v0.15.6.

## Managed fleet licence delivery

If your IT team has a Utterbar Pro licence to roll out across a fleet, they can now drop a single signed file at:

```
%APPDATA%\Utterbar\licence.bin
```

Utterbar reads the file at startup, verifies the Ed25519 signature offline against the public keys baked into the desktop app, and treats the result as the active Pro licence on that machine. The user never sees an activation dialog. Removal is "delete the file".

A few behaviours worth knowing:

- **Managed wins.** A verified `licence.bin` overrides any user-pasted licence cache on the same machine. The user cannot accidentally downgrade a managed deployment by pasting a personal key.
- **Invalid managed files fail closed.** If the file is present but corrupt, the wrong length, or signed with a key the app does not recognise, the machine reports as Free and a warning lands in the app log. Crucially, paste-flow activation is also blocked on that machine until the file is fixed or removed. An admin who pushed a broken file gets a clear "no Pro" signal rather than a quiet downgrade or a user-side override.
- **Activation and device removal are disabled in the app.** Settings, Licence shows a short "Managed by your administrator" notice instead of the activation form. The IT admin handles changes by editing the file on disk.
- **No DPAPI wrapper.** The file is the raw 96-byte signed blob the desktop already verifies. The bytes are not secret in the cryptographic sense (the signature is what makes them trustworthy), so the file can be baked into a golden image or pushed by MDM exactly like any other config file.

The admin website has a matching "Download licence.bin" button on each licence detail page that serves the existing signed blob as `application/octet-stream` with a stable filename. That route was added in this branch but the website rollout is a separate deploy step; admins on the existing utterbar.com build will not see the button until the website is updated.

## New group policy keys

Three new DWORD values under the existing `HKLM\SOFTWARE\Policies\Utterbar` key (with `HKCU` as a fallback). The existing five keys (`UpdateChannel`, `CheckUpdatesAutomatically`, `BlockModelDownloads`, `BlockSystemAudio`, `RequireLicence`) are unchanged.

- **`BlockHistory`** (REG_DWORD, 0 or 1). When 1, Utterbar does not persist new history rows. Existing rows are not deleted; the policy is forward-only ("stop collecting more"), not retrospective. Use for environments where transcript retention is out of scope.
- **`BlockHistoryExport`** (REG_DWORD, 0 or 1). When 1, the "export history as JSON" command refuses. History stays visible in the in-app History page; only the off-device copy is disabled. `BlockHistory` implies this.
- **`BlockTelemetry`** (REG_DWORD, 0 or 1). When 1, the local on-device analytics rollup that powers the Dashboard counters (words, dictations, time saved) does not bump on a successful dictation. There is no remote telemetry; this gates the local SQLite rollup only.

The Privacy settings page now shows a "Disabled by your administrator" hint when any of these three keys are set, so the user can see why the relevant controls behave the way they do.

## Policy changes require a restart

The registry is read once at app start. After pushing a change to any policy value, the user has to close and reopen Utterbar before the new value takes effect. Same contract Windows itself has for most managed policies. This applies to all eight pinnable values, not only the three new ones.

## What this release does not include

To set expectations clearly:

- **No volume or seat-count checkout flow on the website yet.** Multi-seat purchases still go through email. The fleet licence file format described above is the deployment side; the buying side is unchanged.
- **No air-gapped activation workflow yet.** A fully air-gapped machine can still receive a `licence.bin` via sneakernet and run Pro indefinitely without network, but signing a request file offline and ingesting a signed activation file is not in this build.
- **No code-signed installer build automation.** This release ships with the same SmartScreen profile as recent betas. For Business and Enterprise orders where a signed installer is part of the deal, the signing happens at order time outside the standard build pipeline.
