# Utterbar 0.11.0 (beta)

Four features focused on making the app feel like it improves with use.

## Per-app auto-activation

Modes can now switch themselves on automatically based on which app you have focused. The rules editor in the mode editor was already there. This release wires the matcher to a foreground-window watcher, so:

- Match by executable name, window title, or window class. Wildcards (`*`) supported in all three.
- First match wins, scanning your modes in the order they appear in your list. If multiple modes match an app, drag the one you want to win to the top.
- The watcher stays out of your way while you're recording. Modes never switch mid-utterance. A queued switch waits for the next idle moment.
- The watcher polls roughly every 750ms, which is fast enough to feel responsive when you alt-tab and slow enough that the CPU cost is invisible.

Open Settings → Modes → edit a mode → "Auto-activation" to add rules.

## Subtitle export for file transcription

Every completed file-transcription job now writes `.srt` and `.vtt` sidecars next to the existing `.utterbar.txt`. So `meeting.mp4` → `meeting.utterbar.txt` + `meeting.utterbar.srt` + `meeting.utterbar.vtt`.

A note on timing: the underlying ASR wrapper drops per-word timestamps, so this release distributes total audio duration proportionally across sentence boundaries. **The timing is approximate at the sentence level.** It's good enough as a rough subtitle pass to refine in Subtitle Edit, Premiere, Resolve, or whatever editor you use, but it isn't word-perfect. The code is wired to switch to true word-level timing the moment a future engine populates real timestamps; nothing on the user side changes when that happens.

## History → vocabulary loop

The History detail modal now lets you fix mistranscriptions in place:

- Highlight a misheard word or phrase in either the Raw or Processed pane.
- "Add to vocabulary" stores it as a hinted word so future ASR runs score it more highly.
- "Replace with…" creates a literal replacement rule: this came out, that's what I meant. Applied at post-processing time on every dictation.
- Either action triggers a one-click reprocess of the current entry so you can see the fix take effect immediately.

No more copying a wrong word, opening Settings → Vocabulary, pasting it in, switching back. The whole loop happens inside the History modal.

## Better history filtering

The History page now has filters for Mode (any of your modes), App (any executable that's appeared in your history), and a date-range chip group (All time / Today / 7 days / 30 days). All three combine with the existing search box; a "Reset filters" link appears when anything is set.

The backend already stored all of these. This release exposes them.

## Beta

This is a **beta-channel** release. Stable users won't see it in their auto-update toast. To opt in: Settings → General → Updates → Update channel → Beta.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log and any crash dumps. Send the newest files to support and we'll take a look.
