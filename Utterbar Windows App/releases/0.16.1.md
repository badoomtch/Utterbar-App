# Utterbar 0.16.1 (beta)

Beta hotfix for Windows launch-at-login reliability. Stable channel still serves v0.16.0.

## What this fixes

The Settings, General "Launch at login" toggle wrote both your settings file and a Windows registry entry, but in three cases the registry entry could go stale or fail silently while the setting still said enabled:

- Install paths containing spaces (for example `C:\Program Files\Utterbar\utterbar.exe`) silently failed at sign-in. Windows reads the registry value as a command line, splits at the first space, and tried to start `C:\Program.exe`. The new build always double-quotes the executable path so any install path works.
- If the registry entry was removed by a third-party cleaner, antivirus, OS reset, or by a previous reinstall to a different folder, your saved setting still said enabled but the OS had nothing to launch. The toggle never re-asserted itself, so the only fix was to switch the setting off and back on.
- Registry write failures from the toggle were silently swallowed, so neither you nor support saw any error in the logs.

## What this changes

- Utterbar now repairs the registry entry every time it launches. If the saved setting says Launch at login is on, the app re-asserts the entry against the current executable path on every start. A stale or missing entry is healed in place. A repair fires only when the registry does not already match the saved setting, so the common path is a no-op.
- The executable path in the registry value is now always quoted, so any install location works.
- Failures during the toggle and the launch repair are logged via the standard tracing log so support can read them in `%APPDATA%\Utterbar\logs\latest.log`.

## What this does not change

- No website changes.
- No new settings, no new policy keys, no schema or licence changes.
- The user-facing toggle in Settings, General, Launch at login is the same place and behaves the same way. Existing users who already have a working entry see no behaviour change.

## Beta only

Beta-channel release. No `--announce`, no `latest` tag. Stable channel still serves v0.16.0.
