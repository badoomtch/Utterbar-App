# Utterbar 0.17.0

Mainline stable on top of v0.16.0. Bundles the soaked v0.16.1 to v0.16.5 beta line: launch-at-startup repair, ASR prewarm and timing improvements, desktop UX polish, an opt-in deterministic Smart rewrite, and the conferencing output-mute settings clarity work. Local-only, Windows-first, £39.99 one-time.

## What this changes

### Launch-at-startup repair

If you have "Launch Utterbar when Windows starts" turned on, Utterbar now re-asserts the registry entry against the current installer path on every launch. A stale path left behind by a previous install (or stripped by a third-party cleanup tool) is healed automatically. You no longer have to toggle the setting off and back on after a reinstall.

### ASR prewarm and faster cold first dictation

When the default dictation model is configured to stay loaded, Utterbar now prewarms it in the background shortly after launch. The native ONNX and sherpa runtime construction itself is unchanged, but the cost is moved off the first dictation, so the first hotkey press feels faster on a fresh boot. New structured timing logs capture the cold model warm so we can keep this honest in future builds.

### Desktop UX polish

- **Post-update relaunch opens visibly.** When Utterbar restarts itself after applying an update, the window opens instead of hiding straight to the system tray.
- **Meeting Mode shows chunk progress.** During a meeting transcribe, the floating bar surfaces "Transcribing meeting · N/M" with a thin progress track that fills as each chunk completes.
- **Floating bar waveform reacts to the audio level.** The seven bars are now driven by the existing audio meter, so the bar visibly responds to your voice while you dictate. Reduced-motion freezes the row at a static height.
- **Settings sidebar search.** A search field at the top of Settings filters sections by name and curated keyword aliases ("GPU" finds Advanced, "hotkey" finds Shortcuts, "system audio" finds Audio).

### Smart rewrite v1 (deterministic, opt-in)

A new toggle in Settings, Text Output, Formatting: **Smart rewrite**. Off by default. When you turn it on, Utterbar tidies your dictation before it lands in the focused app:

- Removes common filler words like "um", "uh", "like", "you know".
- Normalises spacing (collapses runs of whitespace and trims edges).
- Capitalises the first letter of each sentence.
- Adds a terminal full stop if the sentence ends without one.

The rewrite is **fully local and rule-based**: no AI model is loaded, nothing is sent to a server, no model is downloaded. Best for chat and email-style dictation.

**Turn it off for code dictation.** The capitalise-sentence-starts rule will also capitalise keywords like `let` or `fn`, and the terminal full stop will be added after a closing brace. **Meeting Mode is unaffected** and remains verbatim regardless of this toggle.

### Conferencing output-mute settings (clearer copy and editable list)

The existing "mute conferencing apps while recording" toggle has had its scope made explicit and its app list opened up:

- **Clearer copy.** The toggle is now labelled **"Mute conferencing app output while recording."** It silences what you HEAR from Teams, Slack, Discord, Zoom, and Webex while you are dictating, so call audio and notification dings do not bleed into the room. The audio is restored the moment dictation ends.
- **The toggle does NOT mute your microphone inside those apps.** True per-app microphone mute would require simulating each app's in-call mute shortcut, which is brittle and out of scope for a stable channel feature. If you need to mute your mic to a call, use that app's own mute button.
- **Editable app list.** Settings, Privacy, Media now exposes "Apps to silence" under the toggle. By default it shows the built-in list (Teams.exe, ms-teams.exe, msteams.exe, slack.exe, Discord.exe, DiscordPTB.exe, DiscordCanary.exe, Zoom.exe, ZoomPhone.exe, webex.exe, WebexTeams.exe). Add or remove `.exe` names with the input field and chip buttons. Reset to defaults restores the built-in list. Names match running processes case-insensitively.
- **Validation.** The input rejects paths, drive letters, command lines, quotes, wildcards, and duplicates. Names auto-append `.exe` if you forget. Names over 64 characters are refused.

## Not in this release

Things you may have heard discussed but that are explicitly **not** part of v0.17.0:

- **True per-app microphone mute is NOT in this release.** Output-audio mute only. Your microphone feed into Teams, Discord, Zoom, or Webex is unchanged. Use the call app's own mute button if you need that.
- **Local LLM Smart rewrite is NOT in this release.** Smart rewrite v1 is deterministic and rule-based only. There is no language model running on your PC for rewriting and no cloud rewriting either.
- **Opt-in product analytics is NOT in this release.** Utterbar still sends nothing about your usage to us. The local Dashboard counters remain on-device only.

## What this release does not change

- No changes to ASR runtime DLLs, model files, or the DirectML provider policy. v0.17.0 inherits the same speech runtime as v0.16.0.
- No changes to audio capture, microphone routing, or how Utterbar reads your voice.
- No new policy keys, no schema changes, no licence or telemetry changes.
- No remote calls beyond the existing model download, licence verification, and update check.
- Pricing: still £39.99 GBP one-time for single-user Pro, three-device cap.
- Local-only: nothing leaves your machine. No cloud, no account for the app, no subscription.

## Stable channel

This release supersedes v0.16.0 on the stable channel. Beta-channel users on the v0.16.x line will see 0.17.0 as the next available update. If you have been running a beta and want to stay on stable from now on, switch the channel in Settings, Updates after upgrading.

## If you hit a problem

`%APPDATA%\Utterbar\logs\` has the app log. `crash.log` has any panic traces. Every dictation log line carries provider telemetry, useful for "did GPU acceleration run on this attempt?". If a feature misbehaves, switch Settings, Advanced, GPU acceleration to CPU, then email hello@ddraig.dev with the log file.
