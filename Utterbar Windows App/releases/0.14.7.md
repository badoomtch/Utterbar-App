# Utterbar 0.14.7 (beta)

Mic capture sample-rate fix. Beta channel.

## Recordings sound like the actual microphone again

If you have a quality mic (USB interface, condenser, broadcast mic) and noticed recordings on recent versions sounded thin, hollow, or like a laptop webcam, this release fixes it.

The cause: until now we asked cpal for the device's "default" sample rate via `default_input_config()`. On Windows that follows whatever Sound Control Panel reports for the device, which for a lot of input devices is 16 kHz mono. Capturing a studio mic at 16 kHz is like running 4K footage through a JPEG converter, every frequency above 8 kHz is gone, and that 8 kHz ceiling is exactly the band that gives speech its "presence". The recordings look fine numerically (peak, RMS, format all healthy) but sound flat because the spectrum is gutted.

Why other recording apps on the same hardware sound great: most DAWs and recording tools explicitly request a high sample rate from the device rather than accepting the system default. Utterbar wasn't doing that.

The fix iterates the device's supported input configurations and picks the highest available rate up to 48 kHz. The Focusrite, every consumer USB mic, and every laptop built-in mic supports 48 kHz natively, so this lands on 48 kHz the vast majority of the time. Our existing internal resampler then converts to 16 kHz for the recogniser, which is what Parakeet and Whisper need. The retained .wav files are still saved at 16 kHz post-resample, but the content within that bandwidth is now cleanly reconstructed from a high-quality source rather than bandlimited at the device.

If a device genuinely caps below 48 kHz, we use its highest available rate. Falls back to the previous default-input-config path if the supported-configs API itself fails (some Bluetooth and virtual audio drivers are flaky there).

The capture stream now logs `device_name`, `src_rate`, `channels`, `sample_format` once per recording opened, so a future "is my mic configured right?" diagnostic can read the log to confirm.

## What this won't fix

If a different program records cleanly on the same mic, this fix should bring Utterbar to parity. If the other program also sounds bad, the problem is something in the Windows audio stack (exclusive mode, drivers, gain) rather than us, and the existing Settings → Audio → Microphone selector is the lever.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log. The new "audio capture stream opened" line shows what rate the device is delivering. If it still says `src_rate=16000` after this update, your Focusrite genuinely only supports 16 kHz on this Windows install, which would point at a driver or routing problem rather than our code. Send us the log line and we can dig.
