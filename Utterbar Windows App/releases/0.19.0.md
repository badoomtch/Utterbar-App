# Utterbar 0.19.0

A stable release on top of v0.18.0. Bundles the soaked v0.18.1, v0.18.2, v0.18.3 and v0.18.4 betas into a single stable cut.

## What this changes

Two user-visible changes land on the stable channel:

- **Settings search.** A search box at the top of Settings finds any setting by name, label, or the help text shown next to it. Type "hotkey", "model", "language", "mute", and Settings filters down to the matching panes and rows. Useful when you remember a setting exists but not where it lives. Available in every Settings tab.
- **Experimental Teams and Discord microphone mute.** Off by default, hidden under Settings, Advanced, Experimental. When on for a given app and you start a recording, Utterbar sends the mute hotkey you have configured in that app as a global keystroke. Teams uses Ctrl+Shift+M by default; Discord uses whatever you set under User Settings, Keybinds, Toggle Mute. A small banner appears below the floating bar asking you to glance at the call app's own mute indicator to confirm; Utterbar cannot read the real mute state of the call app, so the banner is the honest version of "we tried, please confirm". When you stop recording, Utterbar sends the same hotkey again to unmute. If the app crashes mid-recording, the next launch warns you that an unmute may not have fired.

## About the experimental mic mute, the boundaries

This feature is shipping in stable but staying labelled experimental in the app, off by default, for a reason. The current limits are:

- **Teams and Discord only.** Zoom and Webex are not supported.
- **No automated verification.** Utterbar does not use UI Automation to read the call app's mute button, and it does not toggle the operating system's microphone capture endpoint. It sends a keystroke and trusts the app received it.
- **No guarantee.** If your Teams or Discord mute hotkey is unbound, rebound, or being intercepted by another app, the keystroke does nothing and you stay live. The banner exists because of this, please confirm in the call app itself.

If those caveats are not acceptable for your situation, leave the toggles off. Stable output-audio mute, which silences your conferencing app's speakers during dictation, is unrelated and unchanged.

## Bundled from the beta line

Everything on the v0.18.x beta line, in one stable cut:

- **v0.18.1 beta.** Settings search v2 reached its current shape, including help-text matching and per-pane drill-down.
- **v0.18.2 beta.** First version of the experimental Teams and Discord mic-mute toggles, with the lifecycle banner and the restore-on-launch warning after a crash.
- **v0.18.3 beta.** Diagnostic logging around the mute path, used to chase down the issues fixed in v0.18.4.
- **v0.18.4 beta.** Fixed three things on the mic-mute path: tray-minimised Discord now mutes correctly (v0.18.2 silently skipped the keystroke when Discord was minimised to the tray), auto-paste after a mic-mute dictation lands in the right window again (the previous path raced Utterbar's own foreground capture), and the floating bar no longer compresses to a thin sliver when the banner is visible (the banner is now positioned absolutely below the pill rather than squeezing it as a flex sibling).

## What this does not change

- **No analytics, no telemetry.** Utterbar still sends nothing about your usage to us.
- **No local LLM rewrite.** Smart rewrite is still the deterministic rule-based pipeline.
- **No changes to speech recognition, audio capture, microphone routing, GPU acceleration, the speech models, or the speech engine.**
- **No website runtime changes.**
- **No licence, Stripe, or auto-updater backend changes.** Same purchase flow, same activation flow, same updater.
- **No new outbound network calls from the desktop app.**

## Stable channel

This release supersedes v0.18.0 on the stable channel. Beta-channel users on the v0.18.x line will see 0.19.0 as the next available update; the v0.18.1 to v0.18.4 beta rows remain in admin as historical soak records. If you have been running a beta and want to stay on stable from now on, switch the channel in Settings, Updates after upgrading.

## If you hit a problem

The app log is at `%APPDATA%\Utterbar\logs\`. If Utterbar crashes, `crash.log` in that folder will have details. The dictation log lines record which speech model and provider ran each attempt, which helps diagnose issues quickly. If the experimental mic mute is misbehaving, the simplest step is to turn the relevant toggle off in Settings, Advanced, Experimental and use the call app's own mute as you were before. Otherwise, email hello@ddraig.dev with the log file and a note about whether the issue happens at start-up, just after an update, or only during dictation.
