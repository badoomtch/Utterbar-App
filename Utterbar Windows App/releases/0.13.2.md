# Utterbar 0.13.2 (beta)

Iteration on v0.13.1 Meeting Mode based on first-day feedback. Beta channel.

## What's new

**Meeting mode no longer auto-pastes the transcript.** The transcript writes to history; the focused app is left untouched. Trying to inject a 5-minute transcript into whatever window happened to have focus was the wrong default — meeting transcripts are reference material, not dictation. The Meetings page in v0.14 will be the proper home for them; for now, open Settings → History to read the transcript.

**Timestamps per chunk.** Each 30-second chunk gets a `[mm:ss]` prefix so a long meeting reads as a stack of timestamped turns instead of one wall of text:

```
[00:00] **You**: Opening remarks here.

[00:28] **Other**: First reply from the other side.

[00:56] **You**: Continued thought…
```

**Speaker tags (mic vs system).** When both the mic and system audio are active (the typical Meeting Mode case), each chunk gets a `**You**:` or `**Other**:` label derived from which side had higher RMS over that chunk's audio window. Imperfect when both sides are talking simultaneously — whoever was louder wins — but a real first step. Real multi-speaker diarisation lands later.

**Success pill shows what actually happened.** When a meeting recording wraps, the floating bar pill now shows:

> Saved · 5:01 · 11 chunks · 799 chars

…for ~3 seconds before decaying back to idle. Until v0.14's Meetings page lands, this is the only "did the meeting record" signal you get without opening the History page.

## Behind the scenes

Audio capture now exposes a `stop_capture_split()` API so meeting mode gets the mic and loopback streams as separate buffers (used for the per-chunk RMS comparison) rather than pre-mixed. Non-meeting recordings keep using `stop_capture()` — same single-buffer behaviour.

The `DictationPhase::Success` variant now carries an optional `summary` payload (duration / chunk count / char count). Ordinary dictations still serialise the field as omitted, so the existing "Inserted" pill is unchanged.

## Deferred from this release

- **Background transcribe queue** — stop a meeting → return immediately → transcribe runs as a queued job → notification on completion → next recording can start without waiting. Targeted for v0.13.3. Today, stopping a 30-min meeting still blocks the bar on Processing for the ~90 s of chunked transcribe work.
- **Meetings page** — separate `/meetings` route, card-based list, LLM summary, export (.txt / .md / .docx). Targeted for v0.14.0; needs the parked llama.cpp work to land for the summary half.

## If something does go wrong

`%APPDATA%\Utterbar\logs\` has the app log. `crash.log` has any panic traces. Send the newest files to `hello@ddraig.dev`.
